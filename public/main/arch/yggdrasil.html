yggdrasil

# Ставим yggdrasil:
sudo pacman -S yggdrasil

# Версия:
yggdrasil -version

# Проверяем что установилось:
pacman -Ql yggdrasil

У меня в списке нет /etc/yggdrasil.conf. Значит, конфигурация ещё не создана.

Документация Arch говорит, что /etc/yggdrasil.conf создаётся при запуске yggdrasil-default-config.service, либо при первом запуске yggdrasil.service.

Создаём конфигурационный файл:

sudo systemctl start yggdrasil-default-config.service
  • Peers: [] – нет заданных исходящих подключений
  • Listen: [] – нет явно настроенных TCP/TLS-слушателей
  • MulticastInterfaces: Beacon: true, Listen: true – Разрешено обнаружение соседних узлов в локальных сетях
  • IfName: auto – Интерфейс TUN выбирается автоматически
  • GroupPassword: "" – Не задан пароль частной группы
  • NodeInfoPrivacy: false – Стандартная информация об узле может передаваться другим участникам по запросу

sudo systemctl start yggdrasil.service

# Проверяем состояние службы:
systemctl status yggdrasil.service

# Проверяем подключённые пиры:
sudo yggdrasilctl getPeers

# Посмотреть информацию о своём узле:
sudo yggdrasilctl getSelf

# В выводе должен появиться интерфейс yggdrasil:
ip -6 addr

Приватный ключ хранится в конфигурационном файле /etc/yggdrasil.conf в самом начале файла. Он так и подписан: PrivateKey.

А вот, чтобы посмотреть публичный ключ, а также IPv6 и ещё некоторую информацию о моём узле, то можно запустить команду (PublicKey вычисляется из PrivateKey):

sudo yggdrasilctl getPeers

Бэкап

Сделать бэкап приватного ключа можно вот так:

sudo yggdrasil -useconffile /etc/yggdrasil.conf -exportkey > /home/mark/yggdrasil.key

# И ограничим права:
chmod 600 /home/mark/yggrasil.key

А можно просто скопировать весь конфиг:

sudo cp -a /etc/yggdrasil.conf /home/mark/yggdrasil.conf.backup
sudo chown mark:mark /home/mark/yggdrasil.conf.backup
chmod 600 /home/mark/yggdrasil.conf.backup

Проблема с Happ:

ip -6 rule show
  # 0:	from all lookup local
  # 9000:	from all unreachable
  # 32766:	from all lookup main

9000: from all unreachable – проблема здесь! Это правило предписывает Linux возвращать ошибку Network is unreachable для трафика, который доходит до приоритета 9000. Поскольку правило lookup main имеет приоритет 32766, оно не успевает примениться.
