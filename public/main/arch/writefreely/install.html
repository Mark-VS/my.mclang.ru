Установка WriteFreely

Тестовый конфиг для проверки:

server {
   listen 443 ssl;
   server_name writetest1.mclang.ru www.writetest1.mclang.ru;
   ssl_certificate /etc/letsencrypt/live/mclang.ru-0001/fullchain.pem; # managed by Certbot
   ssl_certificate_key /etc/letsencrypt/live/mclang.ru-0001/privkey.pem; # managed by Certbot

   location / {
      proxy_pass http://127.0.0.1:8080;

      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
   }

    include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem; # managed by Certbot

server {
   listen 80;
   server_name writetest1.mclang.ru www.writetest1.mclang.ru;

   return 301 https://$host$request_uri;
}

Конфигурация Nginx, которую приводят в пример в официальном гайде по установке WriteFreely (writefreely.org/start):

server {
    listen 80;
    listen [::]:80;

    server_name example.com;

    gzip on;
    gzip_types
      application/javascript
      application/x-javascript
      application/json
      application/rss+xml
      application/xml
      image/svg+xml
      image/x-icon
      application/vnd.ms-fontobject
      application/font-sfnt
      text/css
      text/plain;
    gzip_min_length 256;
    gzip_comp_level 5;
    gzip_http_version 1.1;
    gzip_vary on;

    location ~ ^/.well-known/(webfinger|nodeinfo|host-meta) {
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_pass http://127.0.0.1:8080;
        proxy_redirect off;
    }

    location ~ ^/(css|img|js|fonts)/ {
        root /var/www/example.com/static;
        # Optionally cache these files in the browser:
        # expires 12M;
    }

    location / {
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_pass http://127.0.0.1:8080;
        proxy_redirect off;
    }
}

  • proxy_set_header X-Forwarded-Proto $scheme; – это передача WriteFreely информации о том, какой протокол использовал клиент при обращении к Nginx.
  • proxy_redirect offNginx по умолчанию умеет изменять заголовки Location в HTTP-ответах от upstream и при определённых условиях может переписать этот URL в соответствии с внешним адресом. А при использовании директивы proxy_redirect off мы как бы говорим: «Не переписывай Location в ответах от WriteFreely. Передавай как есть»

Для начала создадим системного пользователя writefreely с домашней директорией в /var/lib/writefreely/:

sudo useradd --system --create-home --home-dir /var/lib/writefreely --shell /usr/sbin/nologin writefreely

# Проверим:
id writefreely

Официальный архив WriteFreely содержит не только бинарник, но и необходимые для работы файлы (templates, static, pages и т.д). Поэтому удобнее держать весь WriteFreely в одном каталоге: /opt/writefreely/.

Создадим этот каталог:

sudo mkdir /opt/writefreely
sudo chown writefreely:writefreely /opt/writefreely

Переходим в этот каталог и скачиваем релиз 0.17.2:

cd /opt/writefreely

sudo -u writefreely wget https://github.com/writefreely/writefreely/releases/download/v0.17.2/writefreely_0.17.2_linux_amd64.tar.gz

# Проверяем владельца  архива. Должен быть writefreely:
ls -lh

# Распаковываем:
sudo -u writefreely tar -xvzf writefreely_0.17.2_linux_amd64.tar.gzip

cd /opt/writefreely/writefreely

# Посмотрим две справки:
sudo -u writefreely ./writefreely --help
sudo -u writefreely ./writefreely config --help

Из вывода видно, что:

  • config generate – создать базовый конфиг автоматически:
  • config start – интерактивная настройка.

Запускаю интерактивную настройку:

sudo -u writefreely ./writefreely config start

Я выбираю: Production, behind reverse proxy, порт 8080,

Public URL: ... тут важно указать публичный адрес моего блога: https://writetest1.mclang.ru/. Этот адрес будет использоваться для формирования абсолютных ссылок.

После завершения настроек появилось два файла: config.ini и writefreely.db. Всё это принадлежит пользователю writefreely.

Прежде чем запускать WriteFreely, нужно ещё сгененировать ключи. Иначе WriteFreely не запустится. Он будет ругаться на отсутствие ключей. Папка keys у нас пустая.

Запросим справку по ключам:

sudo -u writefreely ./writefreely keys --help

# Теперь генерируем ключи:
sudo -u writefreely ./writefreely keys generate

В папке keys создались четыре ключа:

keys/
├── cookies_auth.aes256
├── cookies_enc.aes256
├── csrf.aes256
└── email.aes256

Теперь можно запускать сервер:

sudo -u writefreely ./writefreely serve

Проверим в другом терминале:

curl -I http://127.0.0.1:8080

Nginx

Сейчас сексция location в моём Nginx-конфиге выглядит вот так:

location / {
   default_type "text/plain; charset=utf-8";
   return 200 "Hello World!";
}

Заменим её на:

location / {
    proxy_pass http://127.0.0.1:8080;

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

Теперь можно запускать WriteFreely и проверять сайт в действии через браузер:

sudo -u writefreely ./writefreely serve

[Unit]
Description=WriteFreely Instance
After=syslog.target network.target

#After=syslog.target network.target mysql.service

[Service]

StandardOutput=syslog
StandardError=syslog
WorkingDirectory=/var/www/example.com
ExecStart=/var/www/example.com/writefreely
Restart=always

[Install]
WantedBy=multi-user.target

Я в своём файле заменил только WorkingDirectory и ExecStart на /opt/writefreely/writefreely

Затем:

sudo systemctl daemon-reload
