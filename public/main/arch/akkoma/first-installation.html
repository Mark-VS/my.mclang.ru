First Installation

Прежде всего можно выполнить вот эти два скрипта:

# Проверим версии нужных на пакетов ...
# ... в репозитории Debian:
apt-cache policy elixir erlang-base erlang-dev erlang-nox

# И проверим инструменты сборки:
for p in git gcc make cmake build-essential libmagic-dev; do
    dpkg-query -W -f='${binary:Package} ${Status}\n' "$p" 2>/dev/null
done

Если всё нормально, и всё соответствует необходимым требованиям на официальной страничке с установкой, то идём дальше.

Официальная инструкция Akkoma рекомендует для установки из исходников elixir, erlang-dev, erlang-nox, cmake и libmagic-dev.

У меня уже установлены git, gcc, make, build-essential.

PostgreSQL у меня тоже установлен.

Инструкция говорит, что нам надо ещё установить postgresql-contrib. Но при попытке его установить, APT говорит, что postgresql-contrib здесь не устанавливается отдельно – что вместо него нам нужен пакет postgresql. А postgresql у меня уже установлен самой последней версии.

Можно выполнить для начала симуляцию установки, чтобы убедиться, что APT внезапно не начнёт что-то обновлять или удалять:

sudo apt-get -s install elixir erlang-dev erlang-nox cmake libmagic-dev

Если всё в порядке, устанавливаем зависимости:

sudo apt install elixir erlang-dev erlang-nox cmake libmagic-dev

# Проверяем:

getent group akkoma
ls -ld /var/lib/akkoma
  • -r – создать системного пользователя;
  • -s /bin/false – запретить обычный интерактивный ввод;
  • -m -d /var/lib/akkoma – создать домашний каталог в /var/lib/akkoma;
  • -U – создать одноимённую группу akkoma.

Создадим папку /opt/akkoma и скачаем туда исходники (адрес возможно заблокирован):

sudo mkdir -p /opt/akkoma
sudo chown akkoma:akkoma /opt/akkoma

  • -u akkoma – выполнить команду от имени пользователя akkoma;
  • -H – установить HOME в домашний каталог целевого пользователя;

Нам нужна отдельная роль PostgreSQL и отдельная база данных. Это позволит Akkoma работать независимо от PeerTube, WriteFreely и других приложений.

# Проверим, запущен ли PostgreSQL:

  # active

# Проверим, какие базы данных уже существуют:

Создаём пользователя для Akkoma:


sudo -u postgres createuser --pwprompt akkoma

# Создаём базу данных:

Конф

Официальная инструкция Akkoma для установки из исходников использует задачу mix pleroma.instance gen. Она задаёт вопросы об экземпляре и создаёт конфигурацию, а также SQL-файл для настройки базы данных.

Генерируем конфигурацию Akkoma:


sudo -Hu akkoma env MIX_ENV=prod mix pleroma.instance gen

Предыдущая команда завершилась с MatchError, потому что аргументы --frontend pleroma-fe --ref stable не соответствуют ожидаемому формату в этой версии Akkoma.Предыдущая команда завершилась с MatchError, потому что аргументы --frontend pleroma-fe --ref stable не соответствуют ожидаемому формату в этой версии Akkoma.Предыдущая команда завершилась с MatchError, потому что аргументы --frontend pleroma-fe --ref stable не соответствуют ожидаемому формату в этой версии Akkoma.

Далее около 15 минут компилируются компоненты и если всё прошло нормально, Akkoma начинает задавать вопросы:

  • What domain will your instance use? – akkoma1.mclang.ru
  • What base URL will uploads use? (e.g. https://media.example.come/media). Здесь просят ввести публичный адрес, по которому будут доступны для всех окружающих мои загрузки (файлы, фоточки, видосики и т.п.). Я ввожу: https://akkoma1.mclang.ru/media
  • What is the name of your instance? – Test Akkoma Instance
  • What is your admin email address?
  • What email address do you want to use for sending email notifications?
  • Do you want search engines to index your site? (y/n)
  • Do you want to store the configuration in the database (allows controlling it from admin-fe)? (y/n)
  • What is the hostname of your database? [localhost] – оставляем localhost – PostgreSQL у нас установлен на этом же сервере.
  • What is the name of your database? [akkoma]
  • What is the user used to connect to your database [akkoma]
  • What is the password used to connect to your database? [autogenerated] – вводим свой пароль от пользователя PostgreSQL akkoma.
  • Would you like to use RUM indices? [n] – RUM (Readability, Usability, Maintainability) — это тип индексов PostgreSQL. Оставляем n
  • What port will the app listen to (leave it if you are using the default setup with nginx)? [4000]
  • What ip will the app listen to (leave it you are using the default setup with nginx)? [127.0.0.1]
  • What directory should media uploads go in (when using the local uploader)? [uploads]
  • What directory should custom public files be read from (custom emojis, frontend bundle overrides, robots.txt, etc.)? [instance/static/] – это каталог для дополнительных публичных файлов (эмодзи, файлов переопределения интерфейса и т.п.)
  • Do you want to strip metadata from uploaded images? This requires exiftool, it was detected as not installed, please install it if you answer yes. (y/n) [n] – Пока оставляем n по умолчанию. Эта опция удаляет метаданные из загружаемых изображений — например, EXIF-информацию о модели камеры, дате съёмки и иногда GPS-координатах. Для этого нужен exiftool, которого сейчас нет на сервере. Для тестового экземпляра можно пока ничего не устанавливать и оставить n. Если позже захочешь автоматически удалять метаданные из фотографий перед публикацией, включим эту опцию отдельно.
  • Do you want to read data from uploaded files so clients can use it to prefill fields like image description? This requires exiftool, it was detected as not installed, please install it if you answer yes. (y/n) [n] – оставляем как есть. Тоже что-то из серии извлечения метаданных с помощью exiftools.
  • Do you want to anonymize the filenames of uploads? (y/n) [n] – Эта настройка определяет, будут ли имена загруженных файлов заменяться случайными или обезличенными именами. По умолчанию [n] Akkoma сохраняет исходные имена файлов.

После ответов на все вопросы создаются следующие файлы:

# ...
# Writing config to config/generated_config.exs.
# Writing the postgres script to config/setup_db.psql.
# Writing /opt/akkoma/instance/static/robots.txt.

  # All files successfully written! Refer to the installation instructions for your platform for next steps.
  • config/generated_config.exs — настройки Akkoma, включая домен и подключение к PostgreSQL.
  • config/setup_db.psql — SQL-скрипт для первоначальной настройки базы данных.
  • instance/static/robots.txt — публичный файл для поисковых роботов.

Теперь выполним SQL-скрипт, который генератор создал для настройки базы PostgreSQL (запускаем её от имени пользователя postgres):

cd /opt/akkoma
sudo -Hu postgres psql -f config/setup_db.psql
  # psql:config/setup_db.psql:1: ERROR:  role "akkoma" already exists
  # psql:config/setup_db.psql:2: ERROR:  database "akkoma" already exists
  # You are now connected to database "akkoma" as user "postgres".
  # CREATE EXTENSION
  # CREATE EXTENSION
  # CREATE EXTENSION

В официальной документации Akkoma для Debian указано, что генератор создаёт generated_config.exs, а затем этот файл нужно переименовать в prod.secret.exs. Именно его ищет prod.exs.

Переименовываем /opt/akkoma/config/generated_config.exs в prod.secret.exs:

cd /opt/akkoma
sudo -Hu akkoma mv config/generated_config.exs config/prod.secret.exs

Теперь выполним миграцию базы данных:


sudo -Hu akkoma env MIX_ENV=prod mix ecto.migrate

Теперь следующий шаг — собрать production-версию Akkoma. Выполним:

cd /opt/akkoma
sudo -Hu akkoma env MIX_ENV=prod mix compile
  # warning: `config/prod.secret.exs` not found. You may want to create one by running `mix pleroma.instance gen`
  # 
  # ==> restarter
  # Generated restarter app
  # ==> pleroma
  # Compiling 12 files (.ex)
  # warning: `config/prod.secret.exs` not found. You may want to create one by running `mix pleroma.instance gen`
  #
  # Generated pleroma app

Компиляция завершилась успешно.

warning: `config/prod.secret.exs` not found. You may want to create one by running `mix pleroma.instance gen` – это предупреждение можно пока игнорировать. В моей версии Akkoma генератор записал настройки в generated_config.exs. Не нужно создавать prod.secret.exs вручную

  0p: false # audio-only (creates mp4 without video stream)

Теперь картина стала яснее. В конфигурации PeerTube:

  • transcoding.enabled: true — транскодирование включено.
  • web_videos.enabled: false — создание обычных веб-видео отключено.
  • hls.enabled: true — HLS включён.
  • 0p: false — отдельное разрешение только для аудио отключено.

Проблема PeerTube:

  • Оригинальный видеофайл исправен. В нём есть видеопоток H.264 с разрешением 1920×1080 и аудиопоток AAC.
  • PeerTube создаёт веб-копию web-video, но в результате оказывается только аудиопоток AAC — видеопотока нет.
  • При этом задача транскодирования завершается успешно, то есть PeerTube не распознаёт результат как ошибочный.
  • HLS-версия создаётся нормально: в ней присутствуют и видео H.264, и звук AAC. На собственной странице PeerTube ролик воспроизводится полностью.
  • В Akkoma при просмотре федеративной публикации используется URL веб-копии. Поэтому звук воспроизводится, но изображения нет. В Mastodon тот же ролик работает нормально, поскольку клиент может обрабатывать доступные варианты видео иначе.

HLS-версия — это вариант видео, подготовленный для потокового воспроизведения через интернет. HLS расшифровывается как HTTP Live Streaming.

Краткая формулировка проблемы. PeerTube 8.2.4 при обработке исправного загруженного видео создаёт MP4-файл веб-версии, содержащий только аудиопоток AAC без видеопотока. При этом транскодирование завершается без ошибки, а HLS-версия того же видео содержит оба потока и воспроизводится нормально. Из-за этого некоторые федеративные клиенты, в частности Akkoma, воспроизводят звук без изображения.

Я сначала изменил настройку web_videos: enabled: false на enabled: true в production.yaml. Это не решило проблему. Но когда изменил ту же настройку в local-production.yaml, то проблема решилась.

Превьюшки

media_preview_proxy. Вроде бы как отвечает за генерацию и отображение уменьшенных копий удалённого медиаконтента. Требует включённого media_proxy.

Для генерации превьюшек также нужен imagemagick. Его надо обязательно установить. Иначе, после включения в конфиге этих пунктов, akkoma.service не сможет запуститься. Он будет выдавать жалобу в логах на отсутствие imagemagick и перезапускаться бесконечно.

Поэтому ставим imagemagick:

sudo apt install imagemagick

Akkoma теперь нормально запустился, но эти настройки никак не повлияли на отображение превьюшек с PeerTube'а.

В объекте Video есть поле icon с пятью изображениями JPEG — от 280 × 157 до 1920 × 1080. Значит, проблема не в том, что PeerTube вообще не публикует изображения для федерации.

А ещё мы видим, что preview здесь — это не обложка, а раскадровка (storyboard). Это отдельная функция PeerTube.

Таким образом, на данный момент у нас установлены три факта:

  • PeerTube располагает твоей обложкой.
  • PeerTube передаёт изображения через icon в ActivityPub.
  • Akkoma возвращает адрес MP4 в поле preview_url.

Это указывает на проблему при обработке или сохранении данных на стороне Akkoma. Но пока рано утверждать, что это ошибка самой программы: ещё нужно проверить, как Akkoma выбирает изображение из массива icon.

...

Вот теперь видно, где именно формируется неправильный ответ API. В status_view.ex Akkoma берёт первый элемент массива attachment["url"], а затем использует его href и для видео, и для превью. MediaProxy.preview_url() не выбирает обложку из PeerTube — он получает уже выбранный URL. Поэтому мы и видим MP4 в preview_url.

В transmogrifier.ex Akkoma преобразует вложения, но сохраняет только URL, тип, MIME-тип, размеры, название, описание и blurhash. Поле icon в этом коде вообще не обрабатывается.

Однако есть ещё одна деталь: PeerTube передаёт миниатюры в icon самого объекта Video, а не обязательно в attachment. Поэтому простого добавления обработки icon в этот участок может быть недостаточно.

Открываем конфиг /opt/akkoma/config/config.exs:

# кусок дефолтного конфига:
config :pleroma, :frontend_configurations,
  # akkoma-fe already bundles its own defaults for everything
  pleroma_fe: %{},
  masto_fe: %{
    showInstanceSpecificPanel: true
  }

Я хочу сделать дефолтной breezy-dark. Поэтому добавляю её:

config :pleroma, :frontend_configurations,
  # akkoma-fe already bundles its own defaults for everything
  pleroma_fe: %{
    theme: "breezy-dark"
  },
  masto_fe: %{
    showInstanceSpecificPanel: true
  }
