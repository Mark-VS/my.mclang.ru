DNS, DoH

В ~/.config/Happ/config.json у нас:

"dns": {
    "servers": [
        {
            "address": "8.8.8.8",
            "detour": "direct",
            "tag": "dns-proxy"
        }
    ]
}

А в Advanced Settings в GUI:

TUN DNS Enable              On
TUN DNS Address             1.1.1.1

Но TUN DNS Address: 1.1.1.1 не означает, что sing-box отправляет DNS-запросы на 1.1.1.1 безопасным способом. Это адрес DNS-сервера, а не DoH.

При этом Use DNS from JSON: Off означает, что настройки DNS из JSON (из нашего конфига ~/.config/Happ/config.json) не являются источником DNS-конфигурации TUN.

~/.config/Happ/config.json — это конфигурация sing-box, который Happ запускает для TUN, а не конфигурация самого Xray.

Ставим dnscrypt-proxy:

sudo pacman -S dnscrypt-proxy

По умолчанию он слушает 127.0.0.1:53

# Запускаем dnscrypt-proxy:
sudo systemctl start dnscrypt-proxy

# Потом сразу:
systemctl status dnscrypt-proxy --no-pager

# И проверяем, действитльно ли он слушает порт 53:
ss -lunp | grep ':53'

# И главный тест:
dig youtube.com @127.0.0.1

# т.е. мы пытаемся достучаться  до youtube, используя
# наш локальный dnscrypt-proxy 127.0.0.1:53

Теперь осталось заменить системный dns в файле /etc/resolv.conf на 127.0.0.1. То есть меняем строку nameserver 8.8.8.8 на nameserver 127.0.0.1

Конфиг dnscrypt-proxy: /etc/dnscrypt-proxy/dnscrypt-proxy.toml

Строка с именами серверов по умолчанию у меня в конфиге закомментирована:

# server_names = ['scaleway-fr', 'google', 'yandex', 'cloudflare']

А вот эти настройки на строке 770:

[sources]
[sources.public-resolvers]

означают, что dnscrypt-proxy использует удалённый список публичных DNS-резолверов.

то есть схема у меня такая:

                    ┌─ DNSCrypt/DoH сервер №1
                    │
Arch → 127.0.0.1:53 → dnscrypt-proxy ─┼─ DNSCrypt/DoH сервер №2
                    │
					└─ DNSCrypt/DoH сервер №3

dnscrypt-proxy сам получает список серверов и выбирает из него.
