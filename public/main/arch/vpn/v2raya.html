v2raya запустил отдельный процесс Xray, и Xray сейчас работает с конфигом /etc/v2raya/config.json.

Из конфига видно, что это вообще не TUN.

В конфиге весь JSON записан в одну строку. Его неудобно читать. Но с этим нам поможет утилита jq:

sudo jq . /etc/v2raya/config.json

Вот ключевой момент:

{
  "port": 52345,
  "protocol": "dokodemo-door",
  "listen": "0.0.0.0",
  ...
  "settings": {
    "network": "tcp,udp",
    "followRedirect": true
  },
  "streamSettings": {
    "sockopt": {
      "tproxy": "redirect"
    }
  },
  "tag": "transparent"
}

То есть v2rayA настроил Xray на transparent proxy через REDIRECT.

Упрощённо схема такая:

                   обычная программа
                         │
                         │ TCP/UDP
                         ▼
                  Linux networking
                         │
                         ▼
                  iptables/nftables
                         │
                    REDIRECT
                         │
                         ▼
                 127.0.0.1:52345
                         │
                         ▼

                  dokodemo-door
                    "transparent"
                         │
                         ▼

                    ┌────┴────┐
                    │         │
                  direct    proxy
                    │         │
                    │         ▼
                    │      VLESS
                    │      Reality
                    │      XHTTP
                    │         │
                    └────┬────┘
                         ▼
                      Internet

То есть, ядро Linux перехватывает соединение, перенаправляет его на порт 52345, а Xray уже решает, что с ним делать.

dokodemo-door – это название протокола Xray. В данном случае он используется не как обычный прокси, а как приёмник перехваченных соединений.

  • "followRedirect": true – говорит Xray примерно следующее: соединение пришло через REDIRECT. Посмотри, куда оно первоначально направлялось, и обработай его как прозрачный прокси.
  • "tproxy": "redirect" – здесь redirect означает именно Linux REDIRECT, а не TUN.

А где находится правило REDIRECT ? В конфиге Xray мы видим порт 52345, но сам Xray НЕ заставляет весь компьютер отправлять трафик на этот порт. Это должна делать система – через firewall/netfilter.

У меня v2rayA работает прозрачно, но не через TUN и не через TProxy. Он использует обычный REDIRECT через nftables.

Таблица называется v2rayA, потому что её создаёт v2rayA при запуске. Когда я останавливаю v2rayA, таблица пропадает.

Разберём

  • v2rayA создал отдельную таблицу nftables: table inet v2raya. inet означает, что таблица может работать и с IPv4, и с IPv6. В ней две основные цепочки: tp_pre и tp_out.
  • Входящий трафик попадает в tp_pre
  • Исходящий локальный трафик идёт через tp_out.
  • Самое главное находится здесь: meta l4proto tcp redirect to :52345. Это буквально означает: если это TCP-пакет, перенаправь его на локальный порт 52345.
  • А что делает set whitelist? Это адреса, которые не надо отправлять в прокси. Например, 192.168.1.1 попадает сюда: ip daddr @whitelist return. return означает: выйти из tp_rule и ничего не перенаправлять. Поэтому если я буду обращаться к своему роутеру (192.168.1.1), то это обращение не пойдёт в Xray.
  • set interface { elements = { 127.0.0.0/8, 192.168.1.0/24 } } – а это дополнительные адреса самого компьютера/локальной сети, которые тоже исключаются: ip daddr @interface return

  • meta mark & 0x00000080 == 0x00000080 return – означает: если пакет уже имеет firewall mark 0x80, не перехватывать его повторно.

    А я уже видел у себя в Xray:

    "sockopt": {
    "mark": 128
}

    128 в десятичной системе = 0x80.

    То есть Xray отправляет исходящий трафик с: mark = 128, а nftables видит: mark & 0x80 == 0x80 и говорит: а, этот пакет уже обработан Xray. Не надо отправлять его обратно в Xray. Это очень важная часть конструкции.

  • meta l4proto tcp redirect to :52345 – стоит обратить внимание: здесь ТОЛЬКО TCP. UDP в этих правилах отсутствует. Именно этот nftables-конфиг не перехватывает UDP. При этом Xray inbound на 52345 настроен на "network": "tcp,udp"
