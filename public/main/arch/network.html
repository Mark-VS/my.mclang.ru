Сеть

Файлы:

  • /etc/resolv.conf – DNS-резолвер
  • /etc/gai.conf – GetAddressInfo – нужен для настройки того, как система выбирает IP-адрес (IPv4 или IPv6) при подключении к хосту.
  • /etc/nsswitch.conf – настройка порядка и способов поиска информации о системных объектах, таких как пользователи, группы, хосты, пароли и т.д. Системные функции, такие как getent, getpwnam(), gethostbyname(), используют NSS.
  • /etc/hosts – хосты
  • /etc/hostname – имя компьютера
  • /usr/share/iproute2/rt_tables – словарь соответствия номеров и имён таблиц маршрутизации

У нас в системе по умолчанию две таблицы маршрутизации:

  • local
  • main (таблица по умолчанию)

Таблица main – пустая, а в local содержатся три записи.

ip route show table local
  # local 127.0.0.0/8 dev lo proto kernel scope host src 127.0.0.1 
  # local 127.0.0.1 dev lo proto kernel scope host src 127.0.0.1 
  # broadcast 127.255.255.255 dev lo proto kernel scope link src 127.0.0.1

В правилах выбора таблицы тоже три записи:

ip rule show all
  # 0:	from all lookup local
  # 32766:	from all lookup main
  # 32767:	from all lookup default
  • from all – все запросы
  • lookup <имя_тиблицы> – отправляет в конкретную таблицу за поиском маршрутов

А числа 0, 32766, 32767 – это приоритеты.

Т.е., сначала (0 – самый высокий приоритет) система смортит в таблицу local, затем, если там ничего не найдено, – в main. И в последнюю очередь – в таблицу defaul.

Но таблицы default по факту не существует. По факту у нас только две таблицы: local и main.

В современных системах таблица default обычно не используется. Это исторически предусмотренная стандартная таблица. Это просто ещё один предусмотренный ядром уровень маршрутизации. Теоретически администратор мог положить туда маршруты, которые должны проверяться после main. Но на практике почти никто так не делает. То есть default по-прежнему существует как зарезервированный идентификатор таблицы в системе маршрутизации Linux, но сама FIB-таблица может вообще не быть создана, пока в неё не добавлен хотя бы один маршрут.

# Присваиваем интерфейсу IP-адрес:
sudo ip addr add 192.168.1.3/24 dev enp2s0

Теперь у интерфейса enp2s0 появился IPv4-адрес.

А в таблице local появилась ещё одна запись: local 192.168.1.3 dev enp2s0 proto kernel scope host src 192.168.1.3

Но у интерфейса статус: DOWN. Это значит, что он не работает. Чтобы его включить, надо присвоить ему статус UP:

# Включаем интерфейс(нужно подождать около 2 сек.):
sudo ip link set dev enp2s0 up

Включение инерфейса может происходить не сразу. Нужно подождать 1-2 секунды.

Теперь у нас появилась запись в таблице main: 192.168.1.0/24 dev enp2s0 proto kernel scope link src 192.168.1.3

И появилась ещё одна запись в ip rule: broadcast 192.168.1.255 dev enp2s0 proto kernel scope link src 192.168.1.3

Теперь у нас дожна работать локальная сеть?

# локальный маршрут в таблицу маршрутизации уже добавился автоматический
# но нам нужно добавить маршрут для интернета в основную таблицу main:
sudo ip route add default via 192.168.1.1 dev enp2s0 table main

# Указание таблицы main можно опустить, потому что
# main – это таблица по умолчанию:
sudo ip route add default via 192.168.1.1 dev enp2s0

Теперь у нас в таблице main появилась ещё одна запись: default via 192.168.1.1 dev enp2s0. Теперь все запросы, которые не удовлетворяют предыдущим правилам, будут отправлять на шлюз 192.168.1.1.

Помимо таблицы main, есть ещё таблица local. Смотреть их содержимое можно вот так:

# Посмотреть таблицу main:
sudo ip route show table main

# Посмотреть таблицу local:
sudo ip route show table local

# Посмотреть все таблицы:
sudo ip route show table all

Если вдруг ping 8.8.8.8 работает, а ping servername.ru не работает, то может быть проблема из-за того, что система по умолчанию работает с IPv6. Проверим:

# Укажем явно IPv4:
ping -4 servername.ru

gai.conf

Как сделать, чтобы система по умолчанию работала с IPv4?

Нужно открыть файл /etc/gai.conf и раскомментировать там следующую строку:

precedence ::ffff:0:0/96  100

Теперь можно пинговать адрес и не указывать явно IPv4. Система будет по умолчанию использовать именно IPv4.

rt_tables

rt_tables – это по сути словарь соответствия номеров и имён таблиц маршрутизации.

Утилита rt_tables является частью пакета iproute2.

Сами соответствия хранятся в файле /usr/share/iproute2/rt_tables:

cat /usr/share/iproute2/rt_tables
#
# reserved values
#
255	local
254	main
253	default
0	unspec
#
# local
#
#1	inr.ruhep

Например, если использовать VPN, то может создастся доп. таблица с номером 2022. И она будет отображаться как таблица 2022. Но если мы хотим добавить ей имя, то технически можно вписать его в файл /usr/share/iproute2/rt_tables: 2022 MyCustomName. И тогда мы сможем обращаться к ней по имени: ip route show table MyCustomName

Но лучше не делать это непосредственно в /usr/share/iproute2/rt_tables.

  • /usr/share/iproute2/rt_tables принадлежит пакету iproute2,
  • а /etc/iproute2/rt_tables предназначен именно для локальных настроек администратора.

Поэтому можно создать файл /etc/iproute2/rt_tables и добавить запись туда. ip умеет использовать /etc/iproute2/rt_tables как локальное дополнение к системному файлу.

Это поможет избежать проблем с перезаписыванием файла во время обновления программы.
