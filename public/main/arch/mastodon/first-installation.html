Mastodon First Installation

Основные компоненты:

  • Ruby on Rails – Основная серверная часть;
  • PostgreSQL – База данных;
  • Redis – Очереди и кэширование;
  • Node.js – Streaming API и компоненты интерфейса;
  • Nginx – Веб-сервер и HTTPS;
  • FFmpeg – Обработка мультимедиа.

Официальная документация Mastodon описывает несколько одновременно работающих компонентов:

  • Puma – основной веб-сервер;
  • Sidekiq – обработка фоновых задач;
  • Streaming API – передача обновлений в реальном времени;
  • PostgreSQL – база данных;
  • Redis – кеш и домашние ленты.

Все они потребляют память независимо друг от друга. Так что Mastodon довольно прожорлив – и не столько из-за количества пользователей, сколько из-за своей архитектуры. И рекомендация по оперативной памяти примерно такая: 2ГБ – на грани; 4ГБ – оптимально; 8ГБ – с запасом.

В Mastodon есть специальная настройка: SINGLE_USER_MODE=true. Она автоматически отключает регистрацию новых пользователей и перенаправляет главную страницу на профиль первого пользователя.

И ещё. Mastodon довольно активно кэширует медиафайлы с других серверов Fediverse и если я подписан на сотни аккаунтов, локальное хранилище может постепенно разрастаться. Поэтому лучше не экономить на диске: 40–60 ГБ для начала – разумный выбор.

Технически Mastodon использует Redis-протокол, который поддерживается Valkey. Но официальная инструкция Mastodon предусматривает Redis.

Для Mastodon нам понадобятся дополнительные системные библиотеки и инструменты:

  • ImageMagick или libvips для обработки изображений;
  • FFmpeg для обработки видео;
  • библиотеки для сборки Ruby и gem-пакетов;
  • rbenv и ruby-build для установки Ruby;
  • Yarn через Corepack.

  # 11.19.1
  • curl -fsSL https://deb.nodesource.com/gpgkey/nodesource-repo.gpg.key – скачиваем файл по указанному URL;
  • sudo gpg --dearmor -o /etc/apt/keyrings/nodesource.gpg – GPG получает скачанные данные через |, преобразует ключ из текстового формата ASCII-armored в бинарный формат OpenPGP и записывает его в файл: /etc/apt/keyrings/nodesource.gpg
  • deb [signed-by=/etc/apt/keyrings/nodesource.gpg] https://deb.nodesource.com/node_24.x nodistro main – репозиторий бинарных пакетов. Здесь мы указываем URL-адрес репозитория, а в квадртных скобках с помощью параметра signed-by передаём ключ, которым проверяется подпись этого репозитория; nodistro – означает, что нет привязки к конкретном дистрибутиву – нам не нужно писать "trixie", например. main – в структуре репозитория APT после названия дистрибутива указывается название раздела, в котором находятся пакеты. В данном случае NodeSource использует раздел с названием main. Это не означает, что мы подключили главный репозиторий Debian или его раздел main. Это просто название каталога/раздела внутри репозитория NodeSource.
  • А сама команда tee записывает полученный через конвейер текст в файл: /etc/apt/sources.list.d/nodesource.list. Здесь мы используем tee, а не >, – чтобы сохранить выполнение от sudo.

Важное замечание: Мы не добавили NodeSource как источник доверия ко всем пакетам Debian. Благодаря signed-by этот ключ привязан именно к данному репозиторию. Это более правильный подход, чем добавлять сторонний ключ в глобальное хранилище доверенных ключей APT.

server_name: mastotest.mclang.ru

  --confirmed \
  --approve \
  --role=Owner

Команда создаст пользователя и сгенерирует пароль. Затем мы войдём в аккаунт и сменим пароль на свой.

  • confirmed – подтверждает адрес почты
  • approve – одобряет регистрацию администрацией

Мы сразу при создании пользователя забыли указать опцию --approve, поэтому подтвердим пользователя отдельной командой:

RAILS_ENV=production bin/tootctl accounts approve mark

У нас в конфигурационном файле включено S3-хранилище. Надо его изменить на локальное.

Если в дальнейшем захочется развернуть отдельный S3-сервер для хранения файлов, то стоит приглядеться к Garage. Это опенсорсное ПО (AGPL-3.0), написанное на Rust.

single user mode

Добавлю-ка я ещё эту переменную в конфиг:

SINGLE_USER_MODE=true

И перезагружаем сервисы:

Перенаправление будет происходить с главной страницы сайта на первого пользователя в базе данных. Если у нас несколько пользователей и я хочу перенаправлять на какого-то конкретного, не первого, то тогда лучше оставить SINGLE_USER_MODE=false, а перенаправление организовать через Nginx. Что-то типа:

location = / {
    return 302 /@mark;
}
  • 301 Moved Permanently — постоянное перенаправление. Браузер может закешировать его надолго. Поисковые системы также воспринимают его как постоянный переезд;
  • 302 Found — временное перенаправление. Браузер не должен считать его окончательным адресом.

Ошибка 500

При каждом обновлении страницы вылезает всплывающее окно с кодом 500.

Ошибка 500 возникает не при загрузке ленты, а при запросе рекомендаций аккаунтов:

GET /api/v2/suggestions
status=500

Mastodon пытается получить рекомендации похожих профилей через Elasticsearch. Но Elasticsearch на твоём VPS не установлен и не запущен.

А у меня в конфиге включён ES_ENABLED, а самого Elasticsearch на сервере нет:

ES_ENABLED=true

Просто можно отключить Elasticsearch. поиск по аккаунтам и публикациям в Mastodon переключится на базу данных — это предусмотрено самим кодом приложения.
