Backup

  • PostgreSQL база данных
  • Пользовательские файлы и медиа (вся папка ~/mastodon/live/public/system/)

  • Секреты и ключи: /home/mastodon/live/.env.production

    В этом файле находятся:

    • SECRET_KEY_BASE
    • VAPID_PRIVATE_KEY
    • VAPID_PUBLIC_KEY
    • ACTIVE_RECORD_ENCRYPTION_PRIMARY_KEY
    • ACTIVE_RECORD_ENCRYPTION_DETERMINISTIC_KEY
    • ACTIVE_RECORD_ENCRYPTION_KEY_DERIVATION_SALT

    Особенно важны ключи Active Record Encryption. Они используются для расшифровки зашифрованных данных в базе.

    При переносе нельзя генерировать новые ключи вместо старых. Нужно перенести исходный .env.production без изменений.

  • Конфигурация. Я изменял только файл config/themes.yml. Его и копируем. Все остальные файлы конфигурации – дефолтные;

  • И все изменения во фронтенде, которые я наделал:

    • app/javascript/styles/jopa_application.scss – точка входа
    • app/javascript/styles/jopa/ – здесь у меня содержится мой файлик tokens/theme/_dark.scss, где хранятся мои цвета для тёмной темы

  • Valkey. В моей конфигурации Mastodon использует логическую базу №2: redis://127.0.0.1:6379/2.

    Потеря Valkey не катастрофична: основные данные находятся в PostgreSQL. Однако можно потерять ещё не обработанные фоновые задачи. Ленты пользователей можно построить заново.

    Для полноценного переноса лучше сохранить состояние Valkey. При этом не стоит автоматически предполагать, что файл называется /var/lib/redis/dump.rdb: у тебя Valkey (а не Redis), поэтому сначала нужно посмотреть его фактическую конфигурацию и каталог данных.

Резервная копия PostgreSQL

pg_dump – утилита для резервного копирования PostgreSQL.

sudo -u mastodon pg_dump -Fc mastodon_production -f /tmp/mastodon_production.dump

pg_dump сохраняет содержимое конкретной базы, но не сохраняет глобальные объекты PostgreSQL, например роли пользователей.

Восстановление БД PostgreSQL

Если мы переносим базу данных на новый сервер, сначала нужно создать саму роль PostgreSQL mastodon, если её ещё нет. Например:

CREATE ROLE mastodon WITH LOGIN PASSWORD 'твой_пароль';

Затем создаём пустую базу данных mastodon_production, назначаем её владельцем роль mastodon и заполняем её содержимым из резервной копии:

# Создаём пустую базу данных PostgreSQL:
sudo -u postgres createdb \
  -O mastodon mastodon_production

# Восстанавливаем базу данных из файла:
sudo -u mastodon pg_restore \
  -d mastodon_production \
  /tmp/mastodon_production.dump
  • -O mastodon – назначить владельцем базы роль mastodon.

Valkey

У меня по умолчанию Valkey сам периодически делает резервные копии.

Посмотреть правила автоматического сохранения можно так:

valkey-cli CONFIG GET save
  # 1) "save"
  # 2) "3600 1 300 100 60 10000"

у меня здесь три автоматических правила сохранения RDB в формате интервал_в_секундах количество_изменений:

  • 3600 1 – сохранять, если за последний час произошло хотя бы 1 изменение;
  • 300 100 – сохранять, если за последние 5 минут произошло хотя бы 100 изменений;
  • 60 10000 – сохранять, если за последнюю минуту произошло хотя бы 10 000 изменений.

Эти команды покажут каталог и имя файла резервной копии:

valkey-cli CONFIG GET dir
  # 1) "dir"
  # 2) "/var/lib/valkey"

valkey-cli CONFIG GET dbfilename
  # 1) "dbfilename"
  # 2) "dump.rdb"

Для создания актуального снимка данных используется:

valkey-cli SAVE

SAVE — синхронная операция. Valkey будет занят созданием снимка, пока она выполняется.

Для небольшого VPS это обычно не проблема, но при большой нагрузке лучше использовать BGSAVE. Она создаёт снимок в фоновом процессе:

valkey-cli BGSAVE

Проверим, когда был сделан последний бэкап.

Команда LASTSAVE возвращает Unix timestamp последнего успешного сохранения RDB:

valkey-cli LASTSAVE
  # (integer) 1795295121

# Преобразуем timestamp в обычную дату:
date -d @1795295121
  # Sat Nov 21 21:05:21 UTC 2026

Посмотреть более подробную информацию о сохранениях:

valkey-cli INFO persistence

Или можно просто посмотреть информацию о файле через ls, чтобы выяснить, когда происходила последняя резервная копия:

sudo ls -lh /var/lib/valkey/dump.rdb
   # -rw-rw---- 1 valkey valkey 2.2M Nov 21 21:05 /var/lib/valkey/dump.rdb

То есть, последовательность выполнения бэкапа такая:

  • Останавливаем все службы Mastodon'а (mastodon-web, mastodon-streaming, mastodon-sidekiq)
  • Выполняем команду SAVE и проверяем, что файл dump.rdb обновился;
  • Останавливаем Valkey

  • Перетаскиваем файл dump.rdb туда, куда нам нужно.

    ВАЖНО: файл должен принадлежать пользователю valkey.

Но этот бэкап не имеет смысла делать на регулярной основе. Он и так сам делается. Его имеет смысл делать вручную только перед переездом на новый сервер: делаем вручную бэкап, отключаем Valkey и переезжаем на новый сервер.

Подводим итоги

На регулярной основе нужно делать резервные копии только:

  • базы данных PostgreSQL;
  • папки с пользовательскими медиа-файлами: ~/mastodon/live/public/system/.

Valkey делает бэкапы сам.

А всё остальное сохраняем единожды и никому не показываем:

  • Ключи из /home/mastodon/live/.env.production;
  • конфигурация;
  • мой кстомный фронтенд.
