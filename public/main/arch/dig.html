dig domain-name.ru +noall +answer
  # syu.su.			600	IN	A	193.187.94.218
  • +noal – убирает весь вывод
  • +answer – добавляет только секцию "Answer"
  • +nocmd – скрывает первую строку вывода с номером версии

Достучаться до ютуба, используя гугловский DNS:

dig youtube @8.8.8.8
  # ; <<>> DiG 9.20.27 <<>> youtube.com @8.8.8.8
  # ; (1 server found)
  # ;; global options: +cmd
  # ;; Got answer:
  # ;; ->>HEADER<<- opcode: QUERY, status: NXDOMAIN, id: 22204
  # ;; flags: qr aa rd ra; QUERY: 1, ANSWER: 0, AUTHORITY: 0, ADDITIONAL: 1
  # 
  # ;; OPT PSEUDOSECTION:
  # ; EDNS: version: 0, flags:; udp: 1232
  # ;; QUESTION SECTION:
  # ;youtube.com.			IN	A
  # 
  # ;; Query time: 45 msec
  # ;; SERVER: 8.8.8.8#53(8.8.8.8) (UDP)
  # ;; WHEN: Sat Aug 29 19:33:23 MSK 2026
  # ;; MSG SIZE  rcvd: 40

status: NXDOMAIN означает, что такого домена не существует. NXDOMAIN – Non-Existent Domain

А мы знаем, что Ютуб существует. Значит, домен кто-то подменяет. Давайте поставим dnscrypt-proxy. Это прокси для DNS. Он слушает порт 53.

И теперь укажем его в качестве DNS:

dig youtube.com @127.0.0.1
  # 
  # ; <<>> DiG 9.20.27 <<>> youtube.com @127.0.0.1
  # ; (1 server found)
  # ;; global options: +cmd
  # ;; Got answer:
  # ;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 13641
  # ;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1
  # 
  # ;; OPT PSEUDOSECTION:
  # ; EDNS: version: 0, flags:; udp: 1232
  # ;; QUESTION SECTION:
  # ;youtube.com.			IN	A
  # 
  # ;; ANSWER SECTION:
  # youtube.com.		1523	IN	A	142.251.40.110
  # 
  # ;; Query time: 0 msec
  # ;; SERVER: 127.0.0.1#53(127.0.0.1) (UDP)
  # ;; WHEN: Sat Aug 29 19:48:14 MSK 2026
  # ;; MSG SIZE  rcvd: 56

Теперь всё хорошо. Теперь DNS-запрос не идёт в открытом виде через обычный DNS-маршрут.

То есть, происходит примерно так: я ввожу в браузер доменное имя. Запрос попадает на 127.0.0.1:53 в dnscrypt-proxy. dnscrypt-proxy шифрует его (то ли с помощью DoH, то ли с помощью ещё чего) и отправляет через HTTPS на удалённый DNS-резолвер. Провайдер видит ЧТО это за DNS-резолвер, но не видит содержимое запроса (не видит какой адрес я запрашиваю). DNS-резолвер возвращает IP-адрес домена и теперь мы можем к нему обратиться по IP-адресу.
