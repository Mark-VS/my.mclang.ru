Alfis

Как мы будем запускать Alfis после установки

Бинарник Alfis будем устанавливать в /usr/local/bin/.

Рабочая директория будет здесь: ~/.local/share/alfis/.

А затем запускаем Alfis вот так:

LUMIO_BACKEND=software alfis --work-dir ~/.local/share/alfis

LUMIO_BACKEND – это переменная окружения, которая указывает библиотеке Lumio GUI, какой механизм использовать для отрисовки интерфейса. Она может принимать два значения:

  • gl – аппаратная отрисовка через OpenGL, с использованием видеокарты;
  • software – программная отрисовка, когда изображение интерфейса формируется процессором (CPU).

Если явно не передать переменной LUMIO_BACKEND значение software, то по умолчанию она будет равна gl.

В чём проблема с этим значением, gl?

В моей системе (Arch + Sway) оно приводит к зависанию всплывающего окна "New domain". И никак не получается ничего сделать со своими доменами. А если запустить Alfis, передав ей переменную LUMIO_BACKEND со значением software, то окно исправно работает.

Поэтому если мне нужно запустить Alfis в графическом режиме, то я при его запуске всегда передаю ему переменную LUMIO_BACKEND со значением software.

Через параметр --work-dir мы передаём Alfis путь к рабочей директории. Если эту директорию не указать явно при запуске, то по умолчанию будет использоваться домашняя директория пользователя. И конфиги, и ключи, и всё прочее будет генерироваться в домашней папке. Это неудобно. Обычно используют ~/.local/share/alfis.

Установка

Для начала проверим, установлены ли Rust и Cargo:

rustc --version
cargo --version

Далее:

# Получаем исходники:
mkdir -p ~/tmp/src/alfis-test
git clone https://github.com/Revertron/Alfis.git ~/tmp/src/alfis-test

# И запускаем сборку:
cd ~/tmp/src/alfis-test
cargo build --release

Сборка закончилась.

Бинарник скомпилировался в target/release/.

Скопируем его в /usr/local/bin/:

sudo install -Dm755 ~/tmp/src/alfis-test/target/release/alfis /usr/local/bin/alfis

# Проверяем:
which alfis
  # /usr/local/bin/alfis

Сразу после установки нужно сгенерировать конфигурационный файл alfis.toml, иначе программа не запустится:

# Эта команда вывыдет сгенерированный конфиг в stdout:
alfis --generate

# Создадим рабочую директорию и сохраним туда alfis.toml:
mkdir -p ~/.local/share/alfis
alfis --generate > ~/.local/share/alfis/alfis.toml

Если мы запустим Alfis прямо сейчас, то он будет ругаться на то, что у него нет доступа к 53-му порту.

53-й порт

В сгенерированном конфиге alfis.toml указан дефолтный порт для DNS: 53.

Но в Linux обычному пользователю запрещено слушать порты ниже 1024.

Можно запустить Alfis от sudo, но это не очень хорошая идея с точки зрения безопасности.

Можно поменять порт в конфиге. Например, на 5353.

Но я хочу оставить дефолтный 53-й порт.

Чтобы решить эту проблему, воспользуемся утилитой setcap. Она даст бинарнику нужные нам полномочия:

sudo setcap 'cap_net_bind_service=+ep' "$(which alfis)"

# Проверяем:
getcap "$(which alfis)"
  # /usr/bin/alfis cap_net_bind_service=ep
  • cap_net_bind_service — разрешить программе открывать привилегированные сетевые порты;
  • +e — включить это полномочие при запуске;
  • +p — записать его в список разрешённых полномочий файла.

В конфиге есть ещё настройка forwarders, в которой указан по умолчанию AdGuard. Это DNS-сервер, на который Alfis передаёт запрос, если сам не может разрешить имя:

key_files = ["key1.toml", "key2.toml", "key3.toml", "key4.toml", "key5.toml"]

[dns]
listen = "127.0.0.3:53"

forwarders = ["https://dns.adguard.com/dns-query"]

То есть, если я укажу браузеру не ALFIS-домен, а обычный домен, то он пойдёт разрешать его на dns.adguard.com/dns-query. Но этот сайт у нас заблочен, так что ничего он не разрешит. Поэтому логичней поменять DNS-сервер на гугловский. У меня в /etc/resolv.conf прописаны: 8.8.8.8 и 8.8.4.4. Их я и добавлю:

forwarders = ["8.8.8.8:53", "8.8.4.4:53"]

Перечисление ключей тоже как будто бы бессмыслено на начальном этапе. Это скорее пример (шаблон) того, как и где надо указывать ключи. Там нужно указать или имена реальных файлов с ключами, или сделать массив пустым, если ни одного ключа ещё нет. Впринципе Alfis запустится и так, но будет выдавать ошибки о том, что указанные ключи не найдены. Поэтому просто укажем ему, что у нас нет ключей:

key_files = []

И вот теперь можно запускать Alfis:

LUMIO_BACKEND=software alfis --work-dir ~/.local/share/alfis

# Или вот так, если графический интерфейс не нужен:
alfis --work-dir ~/.local/share/alfist --nogui

После первого запуска начнётся синхронизация.

У меня синхронизация заняла два вечера. Работала в фоновом режиме. В сумме это примерно 4-5 часов.

Во время синхронизации в рабочей директории создаётся файл blockchain.db. В конечном итоге он у меня весил всего 23M.

Синхронизацию можно прерывать. Просто закрываем окно и всё. На следующий день при запуске программы синхронизация продолжится.

Desktop-файл

Чтобы не запускать каждый раз Alfis из командной строки со всеми этими параметры, неплохо было бы прописать этот запуск в desktop-файл.

Выясним, какое имя у десктоп-файла:

grep -ril 'alfis' /usr/share/applications/

  # /usr/share/applications/name.alfis.Alfis.desktop
  # /usr/share/applications/mimeinfo.cache

Вот его содержимое:

# name.alfis.Alfis.desktop

[Desktop Entry]
Categories=Network;P2P;
Exec=alfis %U
GenericName=Alfis client
Comment=Alternative Free Identity System
Icon=alfis
MimeType=application/x-alfis;
Name=Alfis
Terminal=false
Type=Application
StartupNotify=false
StartupWMClass=alfis
Keywords=dns;p2p;

Такой desktop-файл создаётся автоматически, если ставить Alfis из AUR. А если мы ставили Alfis вручную, то и этот файл придётся создать самим.

В desktop-файлах нельзя просто в строчке указать переменную. Для этого используется /usr/bin/env.

Поэтому вместо Exec=alfis %U напишем так:

Exec=/usr/bin/env LUMIO_BACKEND=software /usr/bin/alfis --work-dir /home/mark/.local/share/alfis %U

Добавление домена

Вписываем доменное имя, указываем доменную зону, а затем кликаем по кнопке "Add record".

Пример добавления записи для домена второго уровня:

  • Name: @
  • Type: AAAA
  • TTL: 3600
  • Data host: мой IPv6 Yggdrasil

Пример добавления записи для домена третьего уровня blog:

  • Name: blog
  • Type: AAAA
  • TTL: 3600
  • Data host: мой IPv6 Yggdrasil

Поля Priority, Weight и Port не нужны для обычной AAAA-записи.
