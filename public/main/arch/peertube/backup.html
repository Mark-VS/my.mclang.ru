Бэкап

Что нужно скопировать:

  • storage
  • И отдельно – ключ storage/plugins/data/peertube-plugin-livechat/prosody/data/peertest.mclang.ru.key
  • PostgreSQL-бд
  • Конфигурация PeerTube (/var/www/peertube/peertube-v8.2.4/config/)

Моя база данных в PostgreSQL называется peertube_prod. Поэтому бэкап можно сделать вот так:

sudo -u postgres pg_dump peertube_prod > peertube_prod.sql

А если база данных, была потеряна, то её можно восстановить вот так:

# Сначала создаём пустую базу данных:
sudo -u postgres createdb -O peertube peertube_prod

# и восстанавливаем:
sudo -u postgres psql peertube_prod < peertube_prod.sql

Сжимать storage в .tar.gz скорее всего нет смысла, потому что видео и так уже сжаты, поэтому имеет смысл просто всё это запихнуть в .tar-контейнер:

sudo tar -cf peertube-storage.tar /var/www/peertube/storage

Но создавать .tar-архив имеет смысл, если мы планируем сделать один архив для долгого хранения. Если же мы хотим делать регулярные бэкапы, то это неудобно.

Делаем бэкап PostgreSQL-базы данных:

sudo -u postgres pg_dump peertube_prod > ~/tmp/peertube_prod.sql

ls -l ~/tmp/
  # total 456
  # -rw-rw-r-- 1 mark mark 464276 Aug 30 21:02 peertube_prod.sql

Владельцем бэкап-файла является mark. Почему? Потому что команда состоит из двух частей:

первая часть, pg_dump, выполняется от имени postgres, а вот вторая часть, > peertube_prod.sql, т.е. вывод в файл, выполняется моей оболочкой от имени mark, поэтому владелец файла: mark.

Если нужно делать регулярные бэкапы, то конечно проще делать, например, вот так:

# Копируем всё содержимое папки storage, кроме ключа
# (на копирование ключа у mark'а всё равно нет прав):
rsync -av \
  --exclude='plugins/data/peertube-plugin-livechat/prosody/data/peertest.mclang.ru.key' \
  mark@mclang.ru:/var/www/peertube/storage/ ~/tmp/peertube/

# Копируем базу данных:
rsync -av mark@mclang.ru:~/tmp/peertube_prod.sql ~/tmp/peertube/

# Копируем конфиг:
rsync -av mark@mclang.ru:/var/www/peertube/peertube-v8.2.4/config/production.yaml ~/tmp/peertube/

# И отдельно сохраняем ключ storage/plugins/data/peertube-plugin-livechat/prosody/data/peertest.mclang.ru.key

дополнительно

sudo -u postgres pg_dump peertube_prod > peertube_prod.sql сохраняет содержимое базы PeerTube.

Но можно ещё сделать дамп ролей/глобальных объектов PostgreSQL, чтобы была возможность восстановить сервер полностью:

sudo -u postgres pg_dumpall --globals-only > postgres_globals.sql

Это не обязательно для восстановления самой базы peertube_prod, но полезно при восстановлении всего PostgreSQL-сервера, чтобы не пришлось, например, заново создавать пользователя peertube при переезде на новый сервер.
