corepack – это вспомогательная программа, которая идёт вместе с Node.js и предназначена для управления менеджерами пакетов вроде pnpm и yarn.

Зачем corepack нужен PeerTube? У JavaScript есть несколько менеджеров пакетов: npm, yarn, pnpm. PeerTube использует pnpm.

Corepack позволяет сказать: «Мне нужна конкретная версия pnpm — установи/подключи её и используй её». Например: corepack prepare pnpm@10 --activate. После этого pnpm --version может показать: 10.x.x. И нам не придётся вручную искать, скачивать и устанавливать pnpm.

После обновления сертификата Certbot "любезно" обновит наш Nginx-конфиг. Желательно привести его к более читаемому виду:

server {
   listen 80;
   listen [::]:80;
   server_name peertest.mclang.ru www.peertest.mclang.ru;
   return 301 https://$host$request_uri;
}

server {
   listen 443 ssl;
   listen [::]:443 ssl;
   server_name peertest.mclang.ru www.peertest.mclang.ru;
   http2 on;

   ssl_certificate /etc/letsencrypt/live/mclang.ru/fullchain.pem; # managed by Certbot
   ssl_certificate_key /etc/letsencrypt/live/mclang.ru/privkey.pem; # managed by Certbot
   include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
   ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem; # managed by Certbot

   location / {
      default_type "text/plain; charset=utf-8";
      return 200 "Hello, говнюшонок!";
   }
}

Проверяем работоспособность конфига:

sudo nginx -t

# И если всё в порядке, перезапускаем Nginx:
sudo systemctl restart nginx

Если всё работает нормально, то заменим location на reverse proxy:

server {
   listen 80;
   listen [::]:80;
   server_name peertest.mclang.ru www.peertest.mclang.ru;
   return 301 https://$host$request_uri;
   return 404; # managed by Certbot
}

server {
   listen 443 ssl;
   listen [::]:443 ssl;
   server_name peertest.mclang.ru www.peertest.mclang.ru;
   http2 on;

   ssl_certificate /etc/letsencrypt/live/mclang.ru/fullchain.pem; # managed by Certbot
   ssl_certificate_key /etc/letsencrypt/live/mclang.ru/privkey.pem; # managed by Certbot
   include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
   ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem; # managed by Certbot

   location / {
      proxy_pass http://127.0.0.1:9000;

      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;

      proxy_http_version 1.1;

      client_max_body_size 0;
      proxy_request_buffering off;
   }
}
  • client_max_body_size 0; – не ограничивать размер запроса со стороны Nginx. Для PeerTube это удобно, потому что пользователь может загружать большие видео.

PeerTube уже настроен на локальное хранение. В storage ничего менять не нужно.

storage:
  tmp: '/var/www/peertube/storage/tmp/'
  web_videos: '/var/www/peertube/storage/web-videos/'
  original_video_files: '/var/www/peertube/storage/original-video-files/'
  ...

object_storage:
  enabled: false

А вот object_storage false означает, что S3/объектное хранилище отключено. Для нашего тестового сервера это именно то, что нужно.

SMTP пока не настроен. Для первого запуска это не проблема. PeerTube сможет работать без отправки почты, а SMTP потом можно настроить.

smtp:
  hostname: null

В PeerTube 8.2.4 есть не только обычное локальное хранилище, но и object_storage. Нам сейчас object storage не нужен — для тестового сервера вполне достаточно обычного локального диска.

Создадим каталоги:

mkdir -p /var/www/peertube/storage/{tmp,tmp-persistent,bin,avatars,web-videos,streaming-playlists,original-video-files,redundancy,logs,previews,thumbnails,storyboards,torrents,captions,cache,plugins,well-known,uploads,client-overrides}

Для production PeerTube уже собран в dist, и собирать его через pnpm build нам не нужно.

Прежде чем запускать node dist/server, нужно убедиться, что PeerTube сможет подключиться к PostgreSQL и Valkey и выполнить свои миграции.

PeerTube использует переменную: NODE_ENV=production

Выполним:

NODE_ENV=production node dist/server --help

PeerTube подхватил оба конфига: default.yaml -> production.yaml

Теперь можно проверить полноценный запуск:

NODE_ENV=production node dist/server --benchmark-startup

После этого первого запуска создастся пользователь root и с генерируется пароль. Этот пароль нужно запомнить/сохранить – он выведется на экран, но нигде не сохранится. Посмотреть позже его будет нельзя.

Теперь можно зайти в браузере под юзером root и ввести этот пароль.

Следующий шаг – сделать PeerTube постоянным сервисом

Сейчас мы запускаем PeerTube вручную:

NODE_ENV=production node dist/server

Но после выхода из SSH/перезагрузки он остановится. Поэтому неплохо бы создать /etc/systemd/system/peertube.service

Создаём unit:

sudo nano /etc/systemd/system/peertube.service

Вставляем туда:

[Unit]
Description=PeerTube
After=network.target postgresql.service valkey-server.service
Wants=postgresql.service valkey-server.service

[Service]
Type=simple
User=peertube
Group=peertube
WorkingDirectory=/var/www/peertube/peertube-v8.2.4

Environment=NODE_ENV=production

ExecStart=/usr/bin/node dist/server

Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

Затем:

sudo systemctl daemon-reload

sudo systemctl start peertube
