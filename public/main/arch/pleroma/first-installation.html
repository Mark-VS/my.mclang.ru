Перед установкой зависимостей проверим, что mix доступен именно для пользователя Pleroma:

sudo -Hu pleroma mix --version

mix — это инструмент Elixir, который управляет зависимостями и сборкой проекта.

Hex — менеджер пакетов для Elixir, через который загружаются многие зависимости Pleroma.

# Ставим hex:
sudo -Hu pleroma mix local.hex --force

# Или через прокси:
sudo -Hu pleroma env \
  https_proxy=http://127.0.0.1:10809 \
  http_proxy=http://127.0.0.1:10809 \
  mix local.hex --force

Скачаем зависимости, необходимые Pleroma для сборки и работы:

sudo -Hu pleroma sh -c 'cd /opt/pleroma && mix deps.get'

Собираем приложение:

sudo -Hu pleroma sh -c 'cd /opt/pleroma && MIX_ENV=prod mix compile'

Повылезало множество всяких предупреждений про устаревший конструкции языка, про отсутствующий конфиг, странное сообщение про ошибку украинского перевода и т.п. Но в конечном итоге: Generated pleroma app, а значит компиляция завершилась успешно.

Создаём конфигурацию:

sudo -Hu pleroma sh -c 'cd /opt/pleroma && MIX_ENV=prod mix pleroma.instance gen'
  # Writing config to config/generated_config.exs.
  # Writing the postgres script to config/setup_db.psql.
  # Writing /opt/pleroma/instance/static/robots.txt.
  # 
  #  All files successfully written! Refer to the installation instructions for your platform for next steps.
  #  Please transfer your config to the database after running database migrations. Refer to "Transferring the config to/from the database" section of the docs for more information.

Генератор рекомендует перенести конфигурацию в базу данных после выполнения миграций.

Создалось три файла:

  • config/generated_config.exs – Конфигурация нашего экземпляра Pleroma;
  • config/setup_db.psql – SQL-скрипт создания пользователя и базы PostgreSQL;
  • instance/static/robots.txt – Файл с правилами для поисковых роботов.

Теперь файл generated_config.exs нужно переименовать в prox.secret.exs. А лучше скопировать, чтобы сохранился оригиальный файл:

sudo cp /opt/pleroma/config/generated_config.exs /opt/pleroma/config/prod.secret.exs
# И меняем владельца:
sudo chown pleroma:pleroma /opt/pleroma/config/prod.secret.exs
sudo chmod 640 /opt/pleroma/config/prod.secret.exs

Запускаем скрипт создания пользователя и базы данных PostgreSQL:

sudo -Hu postgres psql -f /opt/pleroma/config/setup_db.psql

config :pleroma, configurable_from_database: true – Эта настройка разрешает хранить изменяемую конфигурацию в базе данных. Именно поэтому генератор упомянул перенос конфигурации после миграций.

Pleroma использует два уровня конфигурации:

  • config/prod.exs — штатные настройки production-режима;
  • config/generated_config.exs — настройки нашего экземпляра, созданные генератором.

Теперь выполняем миграцию базы данных:


sudo -Hu pleroma sh -c 'cd /opt/pleroma && MIX_ENV=prod mix ecto.migrate'

Теперь переносим конфиг в базу данных:


sudo -Hu pleroma sh -c 'cd /opt/pleroma && MIX_ENV=prod mix pleroma.config migrate_to_db'

Делаю пробный запуск сервера:


sudo -Hu pleroma sh -c 'cd /opt/pleroma && MIX_ENV=prod mix phx.server'

Перед запуском Pleroma подправим Nginx-конфиг:


server {
   listen 80;
   listen [::]:80;
   server_name pleroma1.mclang.ru www.pleroma1.mclang.ru;
   return 301 https://$host$request_uri;

server {

   listen [::]:443 ssl; # managed by Certbot

   ssl_certificate /etc/letsencrypt/live/mclang.ru/fullchain.pem; # managed by Certbot
   ssl_certificate_key /etc/letsencrypt/live/mclang.ru/privkey.pem; # managed by Certbot
   include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
   ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem; # managed by Certbot

   client_max_body_size 16M;

   location / {
      proxy_pass http://127.0.0.1:4000;
      proxy_http_version 1.1;

      proxy_set_header Host $http_host;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;

      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "upgrade";
   }
}

И пробуем запустить Pleroma:

sudo -Hu pleroma sh -c 'cd /opt/pleroma && MIX_ENV=prod mix phx.server'

# Если сервер запустился, проверим:

Убираем обои

Дефолтная обоина указан в админских настройках: /images/city.jpg.

Но сервер по-прежнему отдаёт картинку:

curl -s https://pleroma1.mclang.ru/api/pleroma/frontend_configurations | jq '.pleroma_fe.background'
  # "/images/city.jpg"

Фронтенд получает background: "/images/city.jpg" из frontend_configurations.

При этом в базе у меня есть другая настройка: instance.background_image. Она не заменяет pleroma_fe.background.

Нам нужно изменить только background внутри frontend_configurations, например на пустую строку: background: ""

Добавим в конец файла config/prod.secret.exs:

config :pleroma, :frontend_configurations,
  pleroma_fe: %{
    background: ""
  }

И перезагружаем сервер.

Правда, я не очень понял, зачем вообще переносить настройки в базу данных, если всё равно приходится прописывать настройку вручную в файле. Чтобы не перекомпилировалось каждый раз?

Периодически на страничке вылезают всплывающие окна вот с такими ошибками:

  • Error fetching notifications: can't access property "is_seen", e.pleroma is undefined
  • Error fetching notifications: can't convert undefined to object

Ошибки эти всплывают ТОЛЬКО в LibreWolf. В Falkon и в Chromiumf нет никаких всплывающих окон. При этом если открыть страничку Pleroma в приватном окне LibreWolf, то всплывающих окон с ошибка тоже не будет. Я создал новый профиль (about:profiles) и зашёл через него. Ошибки тоже перестали появляться во всплывающих окнах. Вероятно, тут виноваты какие-то особенные "настройки приватности" у дефолтного профиля LibreWolf.
