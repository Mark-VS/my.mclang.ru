Content Security Policy

CSP (Content Security Policy) — это политика безопасности сайта. Сервер отправляет браузеру специальный HTTP-заголовок, который указывает, какие скрипты, стили, изображения и другие ресурсы разрешено загружать и выполнять.

Когда я захожу на только что установленные инстанс Pleroma, то вижу в DevTools в консоли в первой строчке такую ошибку:

Content-Security-Policy: The page’s settings blocked an inline script (script-src-elem) from being executed because it violates the following directive: “script-src 'self'”. Consider using a hash ('sha256-i6UVp+OjwgULV3tkCdG6v8F2aNgEf4Sp/SoeOwYsMHo=') or a nonce.

При этом браузер предлагает конкретный SHA-256-хэш: sha256-i6UVp+OjwgULV3tkCdG6v8F2aNgEf4Sp/SoeOwYsMHo=

Это позволяет разрешить именно один конкретный встроенный скрипт, не открывая выполнение всех встроенных скриптов через 'unsafe-inline'.

В моём случае браузер получил заголовок примерно такого типа: Content-Security-Policy: upgrade-insecure-requests; script-src 'self'; connect-src 'self' blob: https://pleroma1.mclang.ru wss://pleroma1.mclang.ru https:; .... И в этом заголовке есть часть: script-src 'self'.

Этот заголовок можно увидеть в ответе Pleroma, если обратиться к серверу:

curl -I https://pleroma1.mclang.ru

Проверить заголовки политики безопасности инстанса:

curl -sI https://pleroma1.mclang.ru | grep -i content-security-policy

Заголово CSP формирует Pleroma в файле: lib/pleroma/web/plugs/http_security_plug.ex. Именно в нём на строке 52 устанавливается content-security-policy.

Функция headers() добавляет заголовок, а csp_string() формирует его содержимое.

Вот фрагмент:

script_src =
  if @config_impl.get([:http_security, :allow_unsafe_eval]) do
    if @config_impl.get([:env]) == :dev do
      "script-src 'self' 'unsafe-eval'"
    else
      "script-src 'self' 'wasm-unsafe-eval'"
    end
  else
    "script-src 'self'"
  end

В моём случае используется ветка script-src 'self'. Она разрешает загружать JavaScript с собственного сайта, но запрещает встроенные скрипты (inline scripts). То есть, скрипты, которые находятся непосредственно внутри HTML-страницы.

Вот пример, где JavaScript – прямо внутри HTML-элемента. Это тоже считается встроенным кодом и обычно блокируется такой политикой:

<button onclick="alert('Привет!')">Нажми</button>

Как убрать

В моём случае всё дело было в расширении uBlock Origin. Оно у меня включено в LibreWolf даже в приватном режиме. Если отключить это расширение, то ошибка пропадает.

В Falkon вроде всё норм.
