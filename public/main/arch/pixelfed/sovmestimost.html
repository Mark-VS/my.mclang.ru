Совместимость с GotoSocial

Когда я отвечаю с PixelFed-аккаунта на пост, опубликованный в GotoSocial, то в логах получаю ошибки. И ответ не отображается в GotoSocial-посте.

Вот прямая ссылка на мой GotoSocial-пост: https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT

Вот кусок из логов, который появляется в момент ответа:

func=dereferencing.(*Dereferencer).dereferenceStatusAncestors
level=ERROR
username=mark
original=https://pixeltest.mclang.ru/p/mark/993956318224556161
parent=https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT
msg="indirect in_reply_to_uri => https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT"

GTS получил комментарий от PixelFed. Проблема не в доставке. И после этого GTS обнаружил проблему с inReplyTo.

Самое важное: два разных URL одного GTS-поста.

PixelFed говорит: https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT

А GotoSocial считает каноническим ActivityPub URI этого же поста: https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT

То есть:

Web URL:
https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT

ActivityPub URL:
https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT

И GotoSocial специально ругается: indirect in_reply_to_uri

Причём в исходном коде GoToSocial эта ситуация прямо описана: если URI, указанный как inReplyTo, отличается от URI найденного родительского статуса, GTS считает это indirect URL и не связывает ответы через database ID, потому что это может приводить к неожиданным ситуациям.

Подробнее

  • https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT – в браузере. Это публичный URL страницы поста. Именно его GTS показывает пользователю.

  • https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT – это ActivityPub ID объекта.

    То есть, в ActivityPub JSON, который GTS отдаёт для этого поста, скорее всего будет: "id": "https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT"

Оба URL могут совершенно нормально существовать одновременно.

  • /@mark/statuses/... – для человека
  • /users/mark/statuses/... – ActivityPub Object ID

Но в реализации DereferenceStatusAncestors в GoToSocial есть специальная проверка именно для такого случая:

current.InReplyToURI != parent.URI

И при несовпадении GTS пишет: indirect in_reply_to_uri

Причём комментарий в исходнике буквально объясняет логику: GoToSocial считает такой URL косвенным и намеренно не связывает два статуса через database ID, потому что это может приводить к неожиданным результатам.

То есть, это не случайная ошибка. Это предусмотренное поведение GTS.

Сравнение с Mastodon

Mastodon отправил:

"inReplyTo": "https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT"

А PixelFed отправил:

"inReplyTo": "https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT"

Исправление

В app/Transformer/ActivityPub/Verb/CreateNote.php:

'inReplyTo' => $status->in_reply_to_id ? $status->parent()->url() : null,

заменить на:

'inReplyTo' => $status->in_reply_to_id ? $status->parent()->object_url : null,
