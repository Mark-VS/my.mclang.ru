ActivityPub

Когда я отвечаю на чей-то пост (в PixelFed отвечаю на GTS-пост), то PixelFed создаёт в своей базе данных копию оригинального поста. Даже не копию, а запись со всей информацией об оригинальном посте. У этой записи есть свой ID.

Если я хочу найти у себя в базе данных PixelFed все комментарии-ответы, которые я оставлял к этому GTS-посту, то мне нужно искать у себя записи, в которых поле in_reply_to_id содержит id GTS-поста.

У меня в PixelFed шесть проблемных комментариев. Я их оставил к GTS-посту. PixelFed, открывая этот GTS-пост, не хочет их грузить. А GTS их не показывает из-за неправильного inReplyTo. Мне нужно найти их.

Идентификатор GTS-поста я могу взять из строки браузера. У меня он: https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT

Как мне узнать id GTS-поста у себя в PixelFed-записи?

Выполняем в Tinker:

App\Status::where('uri', 'https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT')->first();

В самом начале вывода можно заметить поле id, которое равно: 993780522457985094.

Или можно сразу достать id:

App\Status::where('uri', 'https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT')->value('id');
  # = 993780522457985094

У импортированного GTS-поста есть object_url = https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT, поэтому можно искать и так:

App\Status::where('object_url', 'https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT')->value('id');
  # = 993780522457985094

Немного о полях:

  • id – внутренний id записи в базе PixelFed;
  • uri – идентификатор/URI оригинального ActivitPub-объекта.
  • url – веб-адрес статуса, который можно открыть в браузере
  • object_url – canonical URL самого ActivityPub-объекта. Именно его GTS использует как id в JSON ActivityPub

Видно, что у этих шести статусов uri, url и object_url равны null.

Выполним для одного из них, чтобы найти его:

$s = App\Status::find(993995910870384776);

Теперь в объекте $s содержится конкретный пост (статус) и мы можем использовать его методы и просматривать свойства:

$s->getAttributes();
$s->profile;
$s->permalink();
$s->url();

Удалить конкретный статус:

App\Jobs\StatusPipeline\StatusDelete::dispatch(
    App\Status::find(993995910870384776)
);

dispatch() не удаляет запись прямо сейчас. Он отправляет StatusDelete в Laravel Queue. А уже Horizon должен подобрать эту job и выполнить её.

После удаления проверяем его наличие:

App\Status::find(993995910870384776);
  # = null

Пробуем редактировать статус:

# Достаём конкретный статус:
$s = App\Status::find(993996395739418765)

# Смотим его атрибуты:
$s->getAttributes();

# Присваиваем нужным атрибутам значения:
$s->uri = 'https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT';
$s->url = 'https://syu.su/@mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT';
$s->object_url = 'https://syu.su/users/mark/statuses/01KWPTPKQZEDGD22H5B5G4PDYT';

# Сохраняем:
$s->save();

# И опять проверяем, чтобы удостовериться, что всё верно:
$s->getAttributes();
