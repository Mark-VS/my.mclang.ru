Установка PixelFed

Скачиваю проект в /var/www:

git clone https://github.com/pixelfed/pixelfed.git
cd pixelfed

# По умолчанию мы оказались в ветке dev,
# где идётся разработка.

# Переключаемся на ветку релиза:
git checkout v0.12.7

git status
   # HEAD detached at v0.12.7
   # nothing to commit, working tree clean

Проверяю права:

ls -ld /var/www/pixelfed/
  # drwxrwxr-x 15 mark mark 4096 Aug  8 19:19 /var/www/pixelfed/

Nginx впоследствии должен смотреть в папку /var/www/pixelfed/public. Владелец папки mark:mark. Это нормально. Менять на www-data не нужно.

git describe --tags
  # v0.12.7

Установим PHP-зависимости Pixelfed через Composer (запускаем без sudo):

composer install

После попытки установить зависимости через Composer, я получил кучу предупреждений или ошибок. Composer обнаружил четыре отсутствующих расширения PHP. Не нужно запускать composer update. У меня уже есть composer.lock и мы хотим установить именно зафиксированные в нём версии. Нам нужны:

  • simplexml
  • zip
  • dom
  • xml

simplexml, dom и xml находятся в пакете php8.4-xml, а zip – в пакете php8.4-zip. Это в Debian.

Устанавливаем их:

sudo apt install php8.4-xml php8.4-zip

Ещё раз проверяем, всё ли у нас есть. На Debian/PHP SimpleXML входит в XML-расширение, и его стоит проверить отдельно:

php -m | grep -E 'bcmath|ctype|curl|dom|intl|mbstring|openssl|simplexml|xml|zip'
  # bcmath
  # ctype
  # curl
  # dom
  # intl
  # libxml
  # mbstring
  # openssl
  # random
  # xml
  # xmlreader
  # xmlwriter
  # zip

php -m | grep -i simplexml
  # SimpleXML

Теперь всё на месте. Повторяем:

composer install

PostgreSQL

Для начала нам нужно создать PostgreSQL-пользователя и базу данных. Подключаемся к серверу PostgreSQL:

sudo -u postgres psql


CREATE USER pixelfed WITH PASSWORD '2m6a1r1k';

-- и выходим:
\q

И проверяем подключение:

psql -h 127.0.0.1 -U pixelfed -d pixelfed

Пользователь и база данных созданы. Теперь можно заполнять файл .env.

Nginx

Подправим несколько строчек в нашем Nginx-конфиге:

# корень проекта:
root /var/www/pixelfed/public;

# Для Laravel/PixelFed нужно направлять неизвестные URL в index.php:
try_files $uri $uri/ /index.php?$query_string;

Весь конфиг для pixeltest.mclang.ru у меня выглядит так:

server {
   listen 80;
   server_name pixeltest.mclang.ru www.pixeltest.mclang.ru;

   return 301 https://pixeltest.mclang.ru;
}

server {
   listen 443 ssl;
   ssl_certificate /etc/letsencrypt/live/mclang.ru/fullchain.pem;
   ssl_certificate_key /etc/letsencrypt/live/mclang.ru/privkey.pem;

   include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
   ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem; # managed by Certbot

   server_name pixeltest.mclang.ru www.pixeltest.mclang.ru;
   root /var/www/pixelfed/public;
   index index.php;

   location / {
      try_files $uri $uri/ /index.php?$query_string;
   }

   location ~ \.php$ {
     include fastcgi.conf;
     fastcgi_pass unix:/run/php/php-fpm.sock;
   }
}

Права доступа

Я работаю с исходниками и с Composer от пользователя mark. А вот PHP-FPM работает от пользователя www-data. Когда Laravel пытается создать скомпилированный шаблон storage/framework/views/..., или записать лог storage/logs/laravel.log, то www-data получает Permission denied.

Не нужно делать весь pixelfed, принадлежащим www-data. Дадим владельца www-data только тем каталогам, в которые Laravel должен писать.

sudo chown -R www-data:www-data /var/www/pixelfed/storage
sudo chown -R www-data:www-data /var/www/pixelfed/bootstrap/cache

# Проверяем:
ls -ld /var/www/pixelfed/storage
  # drwxrwxr-x 7 www-data www-data 4096 Aug  8 19:18 /var/www/pixelfed/storage
ls -ld /var/www/pixelfed/storage/logs
  # drwxrwxr-x 2 www-data www-data 4096 Aug  8 19:18 /var/www/pixelfed/storage/logs
ls -ld /var/www/pixelfed/storage/framework
  # drwxrwxr-x 6 www-data www-data 4096 Aug  8 19:18 /var/www/pixelfed/storage/framework
ls -ld /var/www/pixelfed/bootstrap/cache
  # drwxrwxr-x 2 www-data www-data 4096 Aug  9 11:17 /var/www/pixelfed/bootstrap/cache

Проверяем с помощью curl:

curl -I https://pixeltest.mclang.ru
  # HTTP/1.1 404 Not Found
  # Server: nginx
  # Content-Type: text/html; charset=UTF-8
  # Connection: keep-alive
  # Cache-Control: no-cache, private
  # date: Sun, 09 Aug 2026 14:22:46 GMT

Всё нормально. Цепочка Браузер - HTTPS - Nginx - PHP-FPM - Laravel/PixelFed уже работает. Но мы ещё не настроили PixelFed – не создали нормальный .env, – поэтому получаем ошибку 404. Её отдаёт само приложение.

Идём дальше

Проверим, что Laravel видит конфигурацию:

php artisan about
  # ...
  # Storage
  # public/storage ...... NOT LINKED
  # ...

Проверим подключение к PostgreSQL:

php artisan migrate:status
  # ERROR  Migration table not found.

Это нормально на только что созданное пустой базе данных. Laravel ещё не создал таблицу migrations.

Выполняем:

php artisan migrate --force

У меня php artisan about выдал: public/storage .... NOT LINKED. Исправим это:

php artisan storage:link

Следующий важный шаг – очистить и закэшировать конфигурацию

Поскольку .env мы уже настроили, PixelFed стоит заставить Laravel перечитать его и подготовить production-кэш:

cd /var/www/pixelfed

php artisan config:clear
php artisan cache:clear
php artisan route:clear
php artisan view:clear

А затем:

php artisan config:cache
php artisan route:cache
php artisan view:cache

Вот тут у меня возникли проблемы с правами. У папки с кэшем владелец www-datamark.

Меняю права на:

sudo chown -R mark:www-data /var/www/pixelfed/storage
sudo chown -R mark:www-data /var/www/pixelfed/bootstrap/cache
sudo chmod -R 775 /var/www/pixelfed/storage
sudo chmod -R 775 /var/www/pixelfed/bootstrap/cache

Опять проверяем:

php arisan about

Events .... NOT CACHED – это не ошибка. Это не мешает Laravel работать.

Laravel уже видит и использует:

  • PostgreSQL
  • Valkey через Redis-протокол – кэш и очередь
  • PHP-FPM
  • правильный домен
  • правильный APP_KEY
  • правильные runtime-каталоги

Теперь можно смело открывать сайт:

curl -I https://pixeltest.mclang.ru

Или можно открыть PixelFed прямо в браузере.

Создаём пользователя

Для начала вообще проверим, какие есть доступные команды:

php artisan list | grep -Ei 'user|admin'

Посмотреть, какие доступны Passport-команды:

php artisan list | grep -i passport
  #  install:api                               Create an API routes file and install Laravel Sanctum or Laravel Passport
  # passport
  #  passport:client                           Create a client for issuing access tokens
  #  passport:hash                             Hash all of the existing secrets in the clients table
  #  passport:install                          Run the commands necessary to prepare Passport for use
  #  passport:keys                             Create the encryption keys for API authentication
  #  passport:purge                            Purge revoked and / or expired tokens and authentication codes

У меня в конфиге выставлено:

OAUTH_ENABLED="true"

А Laravel Passport использует пару криптографических ключей для OAuth2. Сейчас эти ключи, судя по всему, ещё не были сгенерированы.

Кстати, APP_KEY тут не заменяет Passport keys. Это две разные вещи.

Генерируем ключи:

# Проверяем наличие ключей:
ls -l storage/oauth-*.key

# Генерируем ключи:
php artisan passport:keys

# Опять проверяем:
ls -l storage/oauth-*.key
  # -rw------- 1 mark mark 3322 Aug  9 16:10 storage/oauth-private.key
  # -rw-rw---- 1 mark mark  812 Aug  9 16:10 storage/oauth-public.key

У меня oauth-private.key имеет права 600, поэтому www-data вообще не может его прочитать.

Сменим владельца на www-data:

sudo chown www-data:www-data storage/oauth-*.key

# Проверяем:
ls -l storage/oauth-*.key
  # -rw------- 1 www-data www-data 3322 Aug  9 16:10 storage/oauth-private.key
  # -rw-rw---- 1 www-data www-data  812 Aug  9 16:10 storage/oauth-public.key

Теперь всё в порядке. Теперь PHP-FPM (www-data) должен увидеть наши Passport keys.

# Создаём пользователя:
php artisan user:create

# Делаем его администратором:
php artisan user:admin mark

# Проверяем:
php artisan user:show mark

Теперь можно авторизовывать под своим никнеймом.

Изменение конфигурационного файла

Допустим, я хочу всключить Activity Pub. Я включаю эту настройку в .env:

ACTIVITY_PUB="true"
AP_REMOTE_FOLLOW="true"
AP_INBOX="true"
AP_OUTBOX="true"
AP_SHAREDINBOX="true"

Важно!!! Laravel использует закэшированную конфигурацию, поэтому изменение .env само по себе не будет подхвачено.

После изменения .env нужно обновить конфигурационный кэш:

sudo -u www-data php artisan config:cache

И всё. PHP-FPM перезапускать не нужно.

Посмотреть работоспособность приложения можно в админской панели в разделе "Диагностика".


sudo apt install php8.4-gd
sudo apt install php8.4-imagick
sudo apt install php8.4-redis

У меня в "Диагностике" отображалось: instance actor cached: false и я никак не мог это исправить. Но вдруг всё заработало. Фиг знает как. Стало: instance actor cached: ✅ true


# Посылал запросы типа:
curl -I https://pixeltest.mclang.ru/i/actor
curl -I https://mclang.ru/i/actor

# Обновлял очищал кэши.

У меня в "Диагностике" до сих пор висит в списке переменных такая вот строка: ACTIVITY_PUB – ❌ false. То есть, не смотря на правильные записи в файле .env, PixelFed считает, что федерация выключена.

Это происходит из-за редкой, но известной архитектурной проблемы кэширования Laravel в Pixelfed. В моём файле .env включена директива: ENABLE_CONFIG_CACHE="true".

Когда она активна, Pixelfed принудительно включает внутренний жесткий кэш конфигурации. Иногда этот кэш «залипает» в базе данных или Redis настолько глубоко, что обычная команда php artisan config:cache просто перезаписывает старую ошибку поверх новой, игнорируя реальное содержимое файла .env.

Чтобы принудительно заставить Pixelfed применить настройки ACTIVITY_PUB="true", выполните пошагово следующие команды в терминале:

# Полностью очищаем кэш конфигурации и маршрутов
sudo -u www-data php artisan config:clear
sudo -u www-data php artisan route:clear
sudo -u www-data php artisan cache:clear

# Очищаем ВСЮ оперативную память Redis (там сидит старый конфиг!)
valkey-cli flushall

sudo systemctl restart php8.4-fpm

# Давайте проверим, что выдает Pixelfed в консоли прямо сейчас, без веб-интерфейса. Выполните команду:
sudo -u www-data php artisan config:show app

# После того как вы выполните шаги выше и обнулите Redis, верните статус актора одной командой:
sudo -u www-data php artisan instance:actor
